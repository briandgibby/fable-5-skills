# Output Surface Routing

Use this reference when deciding whether to answer in chat, create a file, edit an artifact, build an app, or produce another inspectable result.

## Surface Choices

- Inline prose: explanations, strategy, reviews, summaries, and lightweight decisions.
- New files: reusable deliverables, specs, reports, scripts, checklists, generated data, or anything the user asks to save, compare, submit, or reuse.
- Edits to existing files: direct modification requests, bug fixes, docs updates, refactors, or user-owned artifacts that should change in place.
- Visuals or diagrams: when they materially improve understanding or are explicitly requested.
- Apps, workflows, or code: when the user asks for a usable tool, site, game, workflow, automation, or implementation.
- External systems: when the requested work lives in a connected service and the connector is the source of truth.

## Avoid Fake Deliverables

If the user asks for an artifact, create or edit the artifact. Do not only paste the content in chat unless the user explicitly asks for a draft-only response.

## Before Creating Files

Establish:

- Writable target directory.
- Source inputs versus generated outputs.
- Naming convention.
- Whether overwriting is allowed.
- How the user will inspect the result.

## After Creating Files

Make the result accessible:

- Provide exact path, URL, branch, commit, screenshot, or verification summary.
- Mention important assumptions.
- Report tests or validation run.
- State anything that remains incomplete.
